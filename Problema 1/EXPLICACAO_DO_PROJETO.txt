5. Formato numerico Q2.14
-------------------------
O projeto usa ponto fixo Q2.14.

Cada numero usa 16 bits:
- 2 bits para sinal/parte inteira
- 14 bits para parte fracionaria

Fator de escala:
2^14 = 16384

Conversao de real para Q2.14:
valor_q214 = valor_real * 16384

Conversao de Q2.14 para real:
valor_real = valor_q214 / 16384

Exemplos:
1,0 em Q2.14 = 16384 = 0x4000
0,5 em Q2.14 = 8192 = 0x2000
45 graus em radianos = pi/4 ~= 0,785398
0,785398 * 16384 ~= 12868 = 0x3244


6. Little endian e bytes low/high
---------------------------------
O ATmega328P e um microcontrolador de 8 bits. Cada registrador guarda 1 byte.
Como os numeros Q2.14 usam 16 bits, cada numero precisa de 2 bytes.

Chamamos esses bytes de:
- low: byte baixo
- high: byte alto

Exemplo:
0x2D42 e um numero de 16 bits.

Ele e dividido assim:
high = 0x2D
low  = 0x42

Na memoria do AVR, a ordem e little endian:
primeiro aparece o byte low, depois o byte high.

Portanto:
42 2D na memoria = 0x2D42

8. Tabela cordic_atan_table_q14
-------------------------------
A tabela cordic_atan_table_q14 guarda os valores atan(2^-i) em radianos,
convertidos para Q2.14.

O CORDIC usa esses valores para fazer pequenas rotacoes sucessivas. A cada
iteracao, o algoritmo decide se soma ou subtrai o angulo da tabela, tentando
fazer o erro angular z se aproximar de zero.

Tabela usada:

i = 0  -> atan(2^0)   -> 12868
i = 1  -> atan(2^-1)  -> 7596
i = 2  -> atan(2^-2)  -> 4014
i = 3  -> atan(2^-3)  -> 2038
i = 4  -> atan(2^-4)  -> 1022
i = 5  -> atan(2^-5)  -> 512
i = 6  -> atan(2^-6)  -> 256
i = 7  -> atan(2^-7)  -> 128
i = 8  -> atan(2^-8)  -> 64
i = 9  -> atan(2^-9)  -> 32
i = 10 -> atan(2^-10) -> 16
i = 11 -> atan(2^-11) -> 8
i = 12 -> atan(2^-12) -> 4
i = 13 -> atan(2^-13) -> 2
i = 14 -> atan(2^-14) -> 1

Como usamos Q2.14, foram adotadas 15 iteracoes: i = 0 ate i = 14.

11. Rotinas implementadas
-------------------------
init_stack
- inicializa a pilha usando RAMEND
- necessario para rcall e ret funcionarem corretamente

init_test_state
- limpa enderecos de debug na SRAM

cordic_rotate_q214
- implementa CORDIC circular em modo rotacao
- entrada: r20:r21 = angulo em Q2.14
- saida: r22:r23 = cos(angulo)
- saida: r24:r25 = sin(angulo)
- saida: r20:r21 = erro angular final z

arithmetic_shift_right_16
- desloca um numero assinado de 16 bits para a direita
- preserva o sinal

q214_mul_signed
- multiplica dois numeros assinados Q2.14
- entrada: r22:r23 = A
- entrada: r24:r25 = B
- saida: r22:r23 = (A * B) >> 14

cordic_polar_to_rect_q214
- converte coordenadas polares para retangulares
- entrada: r18:r19 = raio r em Q2.14
- entrada: r20:r21 = angulo em Q2.14
- saida: r22:r23 = x = r * cos(angulo)
- saida: r24:r25 = y = r * sin(angulo)


12. Regra matematica do CORDIC circular
---------------------------------------
Estado inicial:

x = K
y = 0
z = angulo de entrada

Se z >= 0:
x = x - (y >> i)
y = y + (x >> i)
z = z - atan(2^-i)

Se z < 0:
x = x + (y >> i)
y = y - (x >> i)
z = z + atan(2^-i)

Ao final:
x ~= cos(angulo original)
y ~= sin(angulo original)
z ~= erro angular residual


13. Testes de seno e cosseno
----------------------------
Cada teste grava 7 bytes:

byte 0 e 1 = x = cos(angulo)
byte 2 e 3 = y = sin(angulo)
byte 4 e 5 = z final
byte 6 = numero de iteracoes

Resultados esperados aproximados:

0x0120: FF 3F 04 00 FF FF 0F
0x0128: 6F 37 FF 1F 00 00 0F
0x0130: 42 2D 41 2D FF FF 0F
0x0138: FF 1F 6F 37 00 00 0F
0x0140: 04 00 FF 3F FF FF 0F

Interpretacao do teste de 45 graus:

42 2D = 0x2D42 = 11586
11586 / 16384 ~= 0,707153

41 2D = 0x2D41 = 11585
11585 / 16384 ~= 0,707092

Logo:
cos(45) ~= 0,707153
sin(45) ~= 0,707092

15. Erros encontrados e solucoes
--------------------------------
Erro: Overlap in .cseg

Causa:
Os arquivos cordic_tables.inc e cordic_core.inc foram incluidos no inicio de
main.asm. Como .include funciona como uma copia literal do conteudo, a tabela
e as rotinas foram colocadas antes do vetor de reset em .org 0x0000.

Solucao:
Mover os includes para o final de main.asm:

.include "cordic_tables.inc"
.include "cordic_core.inc"


Erro: Relative branch out of reach

Causa:
Instrucoes condicionais como brlo e brsh so conseguem saltar para enderecos
proximos. A rotina cordic_rotate_q214 ficou grande, entao brlo nao conseguia
voltar ate cordic_rotate_loop.

Solucao:
Trocar:

cpi r28, CORDIC_ITERATIONS
brlo cordic_rotate_loop

por:

cpi r28, CORDIC_ITERATIONS
brsh cordic_rotate_done
rjmp cordic_rotate_loop

Assim o branch condicional salta para uma etiqueta proxima, e o salto longo
usa rjmp.

17. Build e testes automaticos
------------------------------
Foram adicionados scripts na pasta tools/ para reduzir a dependencia de testes
manuais no Microchip Studio.

tools/build.ps1
- chama o assembler oficial avrasm2.exe
- compila Problema 1/main.asm
- gera arquivos em CliBuild/
- falha se houver erro de assembly

Comando:
powershell -ExecutionPolicy Bypass -File tools/build.ps1

Saidas geradas:
- CliBuild/Problema1.hex
- CliBuild/Problema1.lss
- CliBuild/Problema1.map

tools/test-cordic.js
- chama tools/build.ps1
- carrega o arquivo HEX gerado
- emula o subconjunto de instrucoes AVR usado pelo projeto
- executa o programa ate o loop final
- confere automaticamente a SRAM esperada

Comando:
node tools/test-cordic.js

Testes automaticos verificados:
- seno/cosseno para 0, 30, 45, 60 e 90 graus
- polar -> retangular para os casos definidos na bateria de testes

Essa abordagem nao substitui completamente o debug visual do Microchip Studio,
mas permite validar build e resultados principais diretamente pelo terminal.
